# Top 3 risks of taking this POC to production

**1. Latency and reliability depend on two outside vendors.** The 3-second promise rests on Deepgram and the LLM provider, and both have tail latency I measured in this POC: Deepgram occasionally finalized 2–4 s late, and one Claude first token took 3.3 s. At scale, outages and rate limits turn that into silent failures in the middle of an interview. *Mitigation:* track p95 and p99 per stage (the per-answer metrics already exist) with alerting; hedge LLM requests by racing a second provider when the first hasn't produced a token within ~1.2 s; generate speculatively on stable interim transcripts; deploy close to the provider regions; add circuit breakers and a visible "degraded" state instead of a blank answer.

**2. Wrong answers or wrong moments.** A detection miss means no help, a false trigger is distracting, and an answer that invents experience can damage the candidate in a live interview. Today's thresholds are hand-tuned on a few recordings. *Mitigation:* build an evaluation set of real, consented interview recordings with labelled question boundaries; track detection precision and recall plus an LLM-judged groundedness score; run that set as a regression gate on every prompt or threshold change; keep the strict "resume facts only" rule and consider showing which resume line each claim comes from.

**3. Privacy, consent and abuse.** The product records a third party (the interviewer), which in many places requires consent, and it handles resumes full of personal data. Open endpoints can also burn speech and LLM budget. *Mitigation:* clear consent and disclosure flows; stream-only processing with no stored audio and short transcript retention; encryption and data-processing agreements with vendors; authentication, per-user rate limits and spend caps; and a clear acceptable-use policy, given how this kind of tool can be misused.
